  НЕГРОПЕДИЯ — ГАЙД ПО НАПИСАНИЮ СТАТЕЙ (для нейросетей)
================================================================

Версия: 1.0
Формат: plain text
Аудитория: LLM (ChatGPT, Claude, Gemini, локальные модели)

----------------------------------------------------------------
0. ЧТО ТЫ ДЕЛАЕШЬ
----------------------------------------------------------------

Ты пишешь статью для статической энциклопедии «Негропедия».
Энциклопедия читает данные из двух мест:
  - state.json        — индекс всех статей (список)
  - asset/<имя>.json  — сама статья (контент)

Движок (index.html) уже написан. Ты НЕ пишешь HTML.
Ты пишешь ТОЛЬКО JSON. Движок сам всё отрендерит.

Твоя задача на каждый запрос:
  1. Сгенерировать JSON статьи.
  2. Показать, какую строку добавить в state.json.

----------------------------------------------------------------
1. СТРУКТУРА ПРОЕКТА
----------------------------------------------------------------

  /index.html          движок (не трогать)
  /state.json          индекс статей
  /icon.png            иконка
  /asset/<id>.json     файлы статей

Файл статьи ВСЕГДА лежит в asset/.
Путь в state.json пишется БЕЗ префикса asset/.

----------------------------------------------------------------
2. STATE.JSON — ИНДЕКС
----------------------------------------------------------------

{
  "articles": [
    {
      "id": "unikalnyj-id",
      "title": "Название статьи",
      "file": "unikalnyj-id.json"
    }
  ]
}

Правила:
  - id     : уникальный, латиница в нижнем регистре, дефисы вместо пробелов
  - title  : человекочитаемое название (кириллица разрешена)
  - file   : имя файла внутри asset/, совпадает с id + ".json"

Нельзя:
  - пробелы и кириллица в id
  - слэши и точки в file
  - дубликаты id

----------------------------------------------------------------
3. JSON СТАТЬИ — ОБЩАЯ СХЕМА
----------------------------------------------------------------

{
  "title": "Заголовок статьи",
  "content": [
    { "type": "...", ... },
    { "type": "...", ... }
  ]
}

Поля:
  title    : строка (можно опустить — возьмётся из state.json)
  content  : массив блоков, порядок = порядок на странице

Допустимо писать "blocks" вместо "content".
Если указаны оба — используется "content".

Пустой массив content допустим, но нежелателен.

----------------------------------------------------------------
4. ТИПЫ БЛОКОВ (полный список)
----------------------------------------------------------------

4.1 PARAGRAPH / TEXT — абзац
    { "type": "paragraph", "text": "Текст." }
    { "type": "text",      "text": "Текст." }
    Поддерживает инлайн-разметку (см. раздел 5).

4.2 HEADING — заголовок
    { "type": "heading", "level": 2, "text": "Раздел" }
    level: 1..6 (число). Практика: 2–3.

4.3 LIST — список
    { "type": "list", "ordered": false, "items": ["A", "B"] }
    ordered: true  -> нумерованный
    ordered: false -> маркированный
    items: массив строк (или объектов {text: "..."})

4.4 CODE — блок кода
    { "type": "code", "language": "js", "code": "let x = 1;" }
    language: необязательно, только для CSS-класса.
    ВАЖНО: внутри code разметка НЕ парсится.
    Всё выводится как есть.

4.5 QUOTE / BLOCKQUOTE — цитата
    { "type": "quote",      "text": "Цитата." }
    { "type": "blockquote", "text": "Цитата." }

4.6 IMAGE — картинка
    { "type": "image",
      "src": "asset/pic.png",
      "alt": "описание",
      "caption": "подпись" }
    src     : путь относительно index.html (обязательно)
    alt     : для доступности (желательно)
    caption : подпись под картинкой (необязательно)

4.7 TABLE — таблица
    { "type": "table",
      "headers": ["Кол1", "Кол2"],
      "rows": [["a", "1"], ["b", "2"]] }
    headers: необязательно
    rows   : массив массивов; в ячейках работает инлайн-разметка

4.8 HR / DIVIDER — горизонтальная линия
    { "type": "hr" }
    { "type": "divider" }

4.9 LINK — ссылка отдельным абзацем
    { "type": "link", "href": "https://...", "text": "Текст" }

4.10 HTML — СЫРОЙ HTML (ЗАПРЕЩЁН ДЛЯ LLM)
    { "type": "html", "html": "<div>...</div>" }
    Этот блок вставляет HTML БЕЗ экранирования.
    НЕ ИСПОЛЬЗУЙ. Риск XSS. Только для доверенного контента.

----------------------------------------------------------------
5. ИНЛАЙН-РАЗМЕТКА (внутри text/items/cells)
----------------------------------------------------------------

  **жирный**           -> <strong>
  *курсив*             -> <em>
  ***жирный курсив***  -> <strong><em>
  __жирный__           -> <strong>
  _курсив_             -> <em>
  ___жирный курсив___  -> <strong><em>
  ~~зачёркнутый~~      -> <del>
  `код`                -> <code>
  [текст](url)         -> <a href="url" target="_blank">

Порядок применения: сначала код (`...`) защищается,
затем жирный/курсив, потом ссылки.

Работает в:
  - paragraph.text
  - heading.text
  - list.items[]
  - quote.text
  - table.rows[][]

НЕ работает в:
  - code.code (выводится буквально)
  - image.src / alt / caption (экранируются)

----------------------------------------------------------------
6. ЖЁСТКИЕ ПРАВИЛА ДЛЯ LLM
----------------------------------------------------------------

ЗАПРЕЩЕНО:
  - тип "html"
  - любые поля, не описанные в разделе 4
  - вложенные блоки (block внутри block)
  - комментарии в JSON (// и /* */)
  - висячие запятые в массивах/объектах
  - markdown-обёртки ```json ... ``` в финальном ответе
  - HTML-теги внутри text
  - несколько JSON-объектов подряд в ответе

ОБЯЗАТЕЛЬНО:
  - валидный JSON (проверяй мысленно)
  - экранирование кавычек внутри строк: \"
  - экранирование переводов строк: \n (а не сырой Enter)
  - первый блок — paragraph с введением
  - минимум один heading level 2
  - нейтральный энциклопедический тон

----------------------------------------------------------------
7. ПРОМПТ-ШАБЛОН (вставляй в систему)
----------------------------------------------------------------

Ты пишешь статьи для энциклопедии «Негропедия».
Отвечай ТОЛЬКО валидным JSON, без markdown-обёрток.

Схема ответа:
{
  "title": "<заголовок>",
  "content": [ <массив блоков> ]
}

Доступные типы блоков:
  paragraph / text  — абзац
  heading           — заголовок (level 2..3)
  list              — список (ordered: true/false)
  code              — блок кода (language, code)
  quote             — цитата
  table             — таблица (headers, rows)
  hr                — разделитель
  image             — картинка (src, alt, caption)
  link              — ссылка

Инлайн-разметка в text: **жирный**, *курсив*, `код`,
~~зачёркнутый~~, [текст](url).

Запрещено: тип "html", HTML-теги, комментарии, вложенность.

Тема: <ВСТАВЬ ТЕМУ>
Требования: 3–6 разделов (heading level 2), введение,
нейтральный стиль, без воды.

----------------------------------------------------------------
8. ЧЕК-ЛИСТ ПЕРЕД СОХРАНЕНИЕМ
----------------------------------------------------------------

  [ ] JSON парсится (проверил в валидаторе)
  [ ] id уникален и в нижнем регистре
  [ ] file совпадает с реальным именем в asset/
  [ ] нет блока type: "html"
  [ ] нет комментариев
  [ ] нет висячих запятых
  [ ] все строки в двойных кавычках
  [ ] \n для переводов строк внутри text
  [ ] первый блок — paragraph
  [ ] есть хотя бы один heading level 2

----------------------------------------------------------------
9. ЭТАЛОННЫЙ ПРИМЕР
----------------------------------------------------------------

state.json (добавить строку в articles):
{
  "id": "test",
  "title": "Тест",
  "file": "test.json"
}

{
  "title": "Тестовая статья",
  "content": [
    { "type": "paragraph",
      "text": "Введение с **жирным**, `кодом` и [ссылкой](https://example.com)." },
    { "type": "heading", "level": 2, "text": "Список" },
    { "type": "list", "ordered": true,
      "items": ["Раз", "Два", "Три"] },
    { "type": "heading", "level": 2, "text": "Код" },
    { "type": "code", "language": "js",
      "code": "console.log('hi');" },
    { "type": "hr" },
    { "type": "quote", "text": "Цитата в конце." }
  ]
}

----------------------------------------------------------------
10. ЕСЛИ ЧТО-ТО НЕ РЕНДЕРИТСЯ
----------------------------------------------------------------

Открой консоль (F12 -> Console). Смотри ошибки:

  HTTP 404          -> file в state.json не совпадает с именем в asset/
  Unexpected token  -> сломан JSON (запятая, кавычка, комментарий)
  Пустая страница   -> content пустой, либо все блоки неизвестного типа
  Ошибка "Статья не найдена" -> id в state.json и при клике не совпадают

----------------------------------------------------------------
11. КОРОТКО: АЛГОРИТМ ДЕЙСТВИЙ
----------------------------------------------------------------

  1. Придумай id (латиница, дефисы).
  2. Сгенерируй JSON статьи по схеме раздела 3.
  3. Используй только блоки из раздела 4 (без html).
  4. Разметку в text — по разделу 5.
  5. Проверь по чек-листу раздела 8.
  6. Покажи пользователю:
       - строку для добавления в state.json
       - полный JSON файла asset/<id>.json
  7. Всё. Движок сам отрендерит.
